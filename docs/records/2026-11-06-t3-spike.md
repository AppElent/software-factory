# T3 executor spike

Real runs on a throwaway local repo, using `t3@0.1.8-nightly.20261106.4262`. Raw output, with paths redacted, is in [`tests/fixtures/t3/`](../../tests/fixtures/t3/).

| Question | Result | Evidence |
| --- | --- | --- |
| Do worktree runs work? | Yes. `--worktree main --branch x` creates `~/Developer/.worktrees/<repo>/<branch-slug>`. `show --json` reports `branch` and `worktreePath` | `start-wait`, `show-completed` |
| Must a repo be a T3 project first? | Yes. Otherwise exit 1, `No T3 Code project matches '.'`. `t3 project add <path>` fixes it | Observed |
| Without `--wait` | Returns in under a second with `threadId` and `runId`. Poll `show --json` for `thread.status` | `start-nowait` |
| Exit 2 | A question makes `--wait` exit 2, `status: waiting`. `show` then says `status: running`, `pendingRequestCount: 1`. The question text isn't in `show` | `start-ask`, `show-ask` |
| Exit 1 | A failed run exits 1 with `status: failed` and `error` in the JSON | `start-fail` |
| Can `send` answer a native question? | **No.** It queues as the next turn, and the thread stays waiting | Observed |
| One stage per turn | Yes. After a turn the thread sits at `completed` with no active run, and the next `send` starts a run in the same worktree | `stage1`, Build committed in the worktree |
| Send while busy | Accepted, with `delivery: queued`. Nothing is interrupted | `send-a`, `send-b` |
| Interrupt | Not in the CLI. T3's agent tool `t3_thread_interrupt` works, but the factory isn't an agent inside T3 | Observed |
| Cost | **No source.** No cost, usage, or token field in `show` or `list` | `show-completed` |
| Recent output | Assistant text only, through `show --messages N --json`. No tool output | `show-completed` |

## Decisions

- **T3 stays the runner.** [ADR 0002](../adr/0002-t3-runner.md) is accepted.
- **Cost leaves the interface,** as the companion said it would without a source: cost fields, the Cost tab, and the spend limit.
- **Questions use a factory protocol.** Playbooks tell the agent not to use a question tool, and to end the turn with a `factory-question` block, which `send` can answer. If a native request appears anyway (`pendingRequestCount > 0`), the work order says it's waiting in T3 and offers `Open in T3`.
- **Stop keeps its copy,** "at the agent's next step". An immediate stop stays in T3.
- **Live output is the agent's latest messages.** Tool output stays in T3.
- **The factory runs `t3 project add`** the first time it starts work in a project.
